# AFVC 产品说明

## 一句话

AFVC 是面向地铁 AFC 闸机检修的 **Agent 产品**：在可独立使用的「预测 + 维修作业」能力之上，用对话把「看预测 → 给建议 → 排任务 → 收反馈」跑通。

控制台与 HTTP 调用同一套原子能力；没有 Agent 时，两大模块仍可单独使用。

## 用户与场景

| 项 | 说明 |
|----|------|
| 用户 | 一线检修负责人 / 值班调度 |
| 场景 | 根据预测或风险结果，决定优先检修哪些闸机、派谁、何时执行，并记录执行结果 |

行业上常见路径是：预测/建议 → 人工确认 → 工单或任务执行 → 结果回写（与 CMMS/EAM 闭环同类），本产品做的是其中可落地的窄切片，而不是全厂监控大屏。

## 要解决的问题

- 预测输出与现场设备编号对不齐，无法直接派工
- 优先级说不清，安排依赖口头经验
- 计划未结合人员/资源约束，难以执行
- 执行结果回不来，无法判断建议是否有用

## 能力范围

### 在范围内

| 能力 | 说明 |
|------|------|
| 预测模块 | 复发风险、高风险排序、故障类型等输入；实现可占位（外部结果表或统计基线），不把自研算法当产品核心 |
| 维修作业模块 | 今日检修建议（确定性规则、可解释理由）、任务调度与分配、执行反馈 |
| 知识检索 | 手册 / SOP 等，供 Agent 与作业侧调用；不单开第三业务域 |
| Agent | 主产品入口：理解目标、编排原子能力、叙述结果；工单敏感写需 HITL；检修任务写走 HTTP/控制台 |
| 控制台 / HTTP | 与 Agent 共用原子能力，保证模块可独立验收 |
| 遗留快捷（非主叙事） | `diagnose_device` 设备综合聚合；`advise_maintenance` 单设备 SOP/巡检向——**不是**今日检修排序清单 |

### 不在范围内

- 以自研预测大模型或「算法竞赛」作为产品主叙事
- 堆砌展示页、大屏、案例故事页的「大平台」
- 用 LLM / RAG **决定**检修优先级（排序必须是确定性规则；模型只做理解与编排）
- 输出或暗示「已降低成本 / 已减少故障」一类运营结论
